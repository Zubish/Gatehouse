    function switchMode(mode) {

      currentMode = mode;

        document.getElementById("formTitle");

      const footerAction =
        document.getElementById("footerAction");

      const registrationFields =
        document.querySelectorAll(".registration-only");


      if (mode === "signin") {

        title.textContent = "Welcome back";

        footerText.textContent =

        footerAction.textContent =

        registrationFields.forEach(field => {

        });

      } else {

        document.body.classList.remove("signin");

        signupTab.classList.add("active");
        signinTab.classList.remove("active");

        title.textContent =
          "Create your account";

        subtitle.textContent =

        submit.textContent =

        footerText.textContent =

          "Sign in";

        registrationFields.forEach(field => {
          field.style.display = "";
        });

        changeRole(currentRole);
      }
    }


    function changeRole(role) {

      currentRole = role;

      const organizerFields =
        document.getElementById("organizerFields");

      const venueFields =
        document.getElementById("venueFields");


      if (role === "organizer") {

        organizerFields.classList.add("active");
        venueFields.classList.remove("active");

      } else {

        organizerFields.classList.remove("active");
        venueFields.classList.add("active");

      }
    }


    function togglePassword() {

      const password =
        document.getElementById("password");

      const button =
        document.getElementById("passwordToggle");


      if (password.type === "password") {

        password.type = "text";
        button.textContent = "Hide";

      } else {

        password.type = "password";
        button.textContent = "Show";

      }
    }


    function submitForm() {

junior developer mistake (correction)

I’ve completed a thorough code review of the GateHouse codebase.

Key finding

The app has a strong UI/product prototype foundation, but I would not consider the current implementation production-ready, particularly because GateHouse is an access-control system.

The most serious issues are:

The QR system is not actually HMAC-SHA256. It uses a custom integer hash.
The QR signing secret is hard-coded and exposed in frontend code.
Passwords can be stored in localStorage in plaintext.
Backend authorization is largely missing even though JWT authentication exists.
Frontend and backend have two competing sources of truth — localStorage and PostgreSQL.
GatehouseContext.tsx is doing far too much and has become the application's central monolith.
api/index.ts and server/index.ts duplicate the backend.
The frontend points to localhost:5000, while the Express server defaults to 3001.
The /auth/me response has a frontend/backend shape mismatch.
The registration UI collects considerably more information than the backend actually receives.
Google SSO is currently a simulated/fallback flow rather than production OAuth.
Check-in needs an atomic database transaction to prevent simultaneous scanners from admitting the same guest.
The advertised "offline resilience" is currently mostly localStorage fallback, not a secure offline access-control architecture.

I also attempted a dependency installation/build verification, but the environment's npm registry returned a 404 while fetching yn@3.1.1, so I couldn't honestly claim a successful clean build.
